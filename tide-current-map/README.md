# 東京湾の潮と流れマップ（作業用ソース）

`app/` は https://tide-current-map.cutlassfish.tokyo/ のソース（v17エクスポート）に、横須賀沿岸の高解像度潮流モデルの作業を加えたものです。
ホスティング設定（`.openai/`）は含めていません。

- `app/scripts/tidelib.py` / `app/harmonic.js`：潮汐の調和解析・合成（気象庁の調和定数と一致を確認）
- `app/scripts/nested_model.py`：外側（東京湾250m）＋内側（横須賀沿岸50m）の入れ子潮流モデル
- `app/scripts/harmonic-export.py`：計算結果から格子点ごとの調和定数を書き出し（任意日時の流れを合成）
- `app/scripts/ferry-extract.py` / `ferry-harmonics.py`：港湾空港技術研究所の東京湾フェリーADCPから実測流速を取り出し・解析
- `app/scripts/validate-tide.py`：気象庁潮位局との比較

## 現在の状態（2026-11-01）

- 自作モデルの調和定数（`app/data/harmonic-{inner,mid,outer}.*`）は 2026-10-01〜10-31 の30日計算から作成。任意の日時に合成して表示。
  - inner：横須賀沿岸 50m（35.195–35.345N, 139.625–139.815E）
  - mid：観音崎以北・海堡・中ノ瀬・木更津沖 100m（35.20–35.46N, 139.66–139.96E）
  - outer：東京湾・浦賀水道 250m
- 境界の潮位は油壺・館山・岡田・伊東の気象庁天文潮位から求めた調和定数（布良は湾口外で約14分早く、湾内の時刻がずれるため不使用）。
- 検証結果の要約は `app/data/model-validation.json`、詳細は `app/data/validation-detail.json`。
- 未解決：観音崎北側の強い流れ（公式推算 平均0.8kn・最大1.8kn）をモデルは弱く出す（平均0.4〜0.55kn）。湾口の岸寄りは潮汐以外の流れが大きい。
- 再計算：`python scripts/nested_model.py --days 30 --spinup 48 --start 2026-10-01T00:00 --out run.npz`（50m、約2.5時間）、
  100m は `--inner-bounds 35.20,35.46,139.66,139.96 --inner-dx 100 --inner-dt 20 --inner-nu 2`。書き出しは `scripts/harmonic-export.py`。
- `scripts/qa-*.cjs` は旧UI（10/24事例）前提のままで未更新。

## 2026-11-02 の見直し（自己評価を受けた修正）

- **通信量**：調和定数のバイナリを gzip のまま配信し、ブラウザ側で展開する方式に変更（`<path>.bin.gz`、`DecompressionStream` 非対応時は `<path>.bin` に自動で戻る）。50m格子 7.4MB → 約1.9MB。
- **向きの検証**：海保推算図の矢印を画像から読み取り（`scripts/jcg-arrows.py`）、向きを比較（`scripts/validate-direction.py`）。全体84%が30°以内。観音崎北は反転時刻が合い、向きが約25°反時計回り、速さは約半分。第二海堡北側は約60°のずれ。猿島沖・横須賀沖は矢印が重なり読めない（未比較）。
- **流量の検算**：観音崎北の断面を通る潮汐流量はモデル約6.0万m³/s、湾内の潮位変化から必要な量は約6.3万m³/s で一致。速さの不足は断面全体ではなく、表層・水路中央への集中が出ないため。
- **10/24観察**：モデルは8:30に南東寄り、9:45ごろ反転。観察（11時まで同じ向き）とは反転時刻が1時間以上ずれる。
- 参考点を「猿島沖」「走水沖（台船付近・仮）」「観音崎北」中心に変更。台船の位置は未確認。
- 感度実験（粘性 0.3/8 m²/s、底面抵抗 0.0015、4日間）は `scratchpad` で実施。結果は本文の報告を参照。

- **岸際の流速（2026-11-02 追試）**：陸の境界を「すべり有り」に変更して1日分を試験計算したが、岸から100mの流速は0.10→0.12kt とほぼ変わらず。岸際が弱いのは粘性の帯ではなく、浅い所（水深5〜10m）で底面摩擦が効くため（沖の約1/3）。調和定数データは旧計算のまま有効なので再計算していない。
- **感度実験の結果（4日間、2026-10-24〜）**：内側格子の粘性 0.3 / 1（標準）/ 8 m²/s、底面抵抗 0.0015 / 0.0025（標準）のいずれでも、観音崎北の速さは海保推算の約55〜57%、向きの偏り約−20〜−28°、第二海堡北側の向きの偏り +33〜+55° で、パラメータ調整では埋まらない。標準値を維持。

## 房総（外房・内房）の追加（2026-11-02）

- 水深：`app/scripts/fetch-gttm-boso.py` → `app/data/gttm-boso.npz`（34.80–36.00N, 139.55–141.10E、2秒、int16デシメートル）。
- 計算：`python scripts/nested_model.py --region boso --outer-dx 500 --outer-nu 10 --inner-bounds 34.90,35.36,139.70,139.93 --inner-dx 200 --inner-dt 20 --inner-nu 2 --days 30 --spinup 48 --start 2026-10-01T00:00 --out boso.npz`（約70分）。
- 書き出し：内側 → `harmonic-uchibo`（200m）、外側 → `harmonic-boso`（500m）。
- 表示の優先順位：inner(50m) → mid(100m) → outer(東京湾250m) → uchibo(200m) → boso(500m)。東京湾内は潮位に合わせた湾モデルを優先し、内房南部・外房だけ新格子を使う。
- 湾内の潮位検証（房総モデル単体）：誤差3.6〜4.5cm、M2の時刻が約10〜12分早い（湾内では表示に使っていない）。
- 外房は黒潮・沖合の海流が支配的なことが多く、潮汐のみのこの計算は参考程度。

## 起動の高速化（2026-11-03）

- 潮流データを32×32セルの区画に分け、列ごとに隣のセルとの差分を int16 で持って gzip（全体 4.9MB → 2.4MB）。画面に映る区画と選択地点・表示中の参考点の区画だけを読む。
- 格子のメタデータは index.json に同梱（往復1回減）。区画が届いたらその区画だけ合成。
- 旧来の静的背景画像（coastal-map / overview、計0.8MB）は読まない。Googleフォントは描画を止めない読み込みに、JSモジュールは modulepreload。
- 計測（Playwright、CPU 1/4・4G相当）：流れが出るまで 約15秒 → 約4.5秒。制限なしで約1.5秒。
