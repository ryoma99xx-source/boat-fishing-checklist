# SHIO — 岸際の流れを見る

東京湾の地図をタップし、流向・流速・水深・岸との関係を確認する試験アプリ。
表示対象は北緯35.08〜35.72、東経139.48〜140.15（湾奥〜勝山沖、三浦半島を三崎まで）。
縮小すると青枠で表示対象、緑破線で選択中の計算範囲を示す。

## 2つの表示

- **潮流モデル**：入れ子の潮汐モデル（横須賀沿岸50m＋東京湾250m）の調和定数から、任意の日時の流れを合成する（下記「潮流モデル（調和合成）の表示」）。以前の日付による方式切替（10/24の250m試験／100m定常参考）は廃止。
- **沖合の公式推算**：海上保安庁の公式図から読み取った沖合41地点。選択地点そのものの局所予報ではない。

50m/250mは計算格子であり精度ではない。対象外の海域には値を出さない。「10/24の観察事例を表示」で2026-10-24 8:30と観察地点へ移動する。
観察地点35.279N,139.708Eは写真からの概算で、設定画面で修正できる。
ユーザー申告の実測水深60〜65mに対し、この仮置き位置のGtTM水深は約46m。約400〜500m東では約61〜65mになるが、水深だけでは位置を一意に決められないため、ピンを自動移動していない。
250m試験はこの地点で9時台に反転するため、11時まで朝の向きが続いたという観察を再現できていない。係数を観察に合わせて調整していない。

## 潮流モデル（調和合成）の表示

「潮流モデル」は日付による方式切替をやめ、どの日付・時刻（JST、30分刻み、0〜24時）でも同じ入れ子の潮汐モデルを使う。旧100m定常参考・10/24の250m試験は画面から外した（コードとデータファイルは残し、配信バンドルからは除外）。

- データ：`data/harmonic-outer.*`（東京湾・浦賀水道、250m格子）と`data/harmonic-inner.*`（横須賀沿岸、50m格子、無くても動作）。セルごとの平均流＋12分潮の係数（int16、mm/s）を`harmonic.js`で合成する。
- 優先順位：50m格子の範囲内は50mの値だけを使い、そこで陸・浅場なら値なし。範囲外は250m。どちらにも入らなければ値なし。粗い格子や近くの値で代用しない。格子内はセル中心の双一次補間（陸のセルは補間に入れない）。1 m/s = 1.94384 kt。
- 読み込み：`/api/harmonic/index.json`（no-cache）が各格子の内容ハッシュ付きURL（meta・係数・水深）を返す。250mを先に読み、50m（約7MB）は地図や選択地点が横須賀沿岸にかかったときに後から読む。取得中・失敗中はその範囲に値を出さない。
- ビルド：`worker/harmonic-build.mjs`がwetIdsを連続区間（開始,長さ）へ圧縮し、水深をuint16（0.1m単位）へ変換、係数.binはそのままgzipしてバンドル。Workerは`frameResponse`で展開して元のバイト列を返し、HTTP圧縮はホスティング側に任せる（二重圧縮の再発防止）。配信バイト列と元ファイルの一致をテスト。`data/model-validation.json`があれば実測比較として画面と計算方法に表示（形式：`{summary, items:[{label,value,note}], updated, source}`）。
- 地図：選んだ時刻の流れを固定し、粒子（線の軌跡）を動かす。弱い流れ（0.1〜0.3kt）も見えるよう画面上の速さは√ktに比例させて誇張。背景色は流速（濃紺→青→水色→緑）。陸・範囲外に入った粒子は海上へ再配置。粒子数は表示面積に応じて約1500〜3000、操作中・非表示タブでは停止。標準地図・Google地図（OverlayView）の両方に対応。
- 目印：選択地点（「モデル0.1kt」）、固定の参考点（猿島東・新安浦沖・走水沖・観音崎沖、すべて「モデル」表記）、10/24の観察（目視、流速未計測）。実測値と表記しない。
- 釣り場：`spots.js`の赤い破線は仮の目安（GtTM水深で頂点・辺が海上になることだけ確認）。利用者が修正する前提。
- 含まないもの：風、河川、密度流、黒潮の影響、二枚潮、干出。湾口のフェリーADCP観測（港湾空港技術研究所, 2023）では潮汐以外の流れが潮汐流と同程度あり、実際の流れとは大きく異なることがある。50m・250mは格子間隔で精度ではない。実測未検証。

## 地形

Naotaka CHIKASADA (2020), NIED GtTM。2秒角、約50m間隔。CC BY 4.0。
内閣府の津波用地形などを統合した地形で、元測量の密度・年代・鉛直基準面は場所により異なる。
東京湾周辺を抽出し、緯度を昇順へ並べ、計算格子へ補間した。
GtTMの元ファイルは正が水深、負が陸上標高。既知の陸・海地点で符号を確認。
`data/gttm-provenance.json`のsha256は抽出したfloat32水深配列のバイト列（NPZファイル全体ではない）。
現代の細かな堤防・台船・狭い港内まで解像するデータではない。格子間隔は予報精度を保証しない。

## 時間変化モデル

`ShallowWater`は固定湿潤域の水深平均自由水面試験モデル。
MAC格子、線形化した連続式、陰的重力波、陽的風上移流・粘性・コリオリ、半陰的二次底面抵抗。
水深3m以上で海に接続するセルを対象とし、陸地を横切る面流量はゼロ。
外縁の海セルに油壺Z1・布良MRの気象庁天文潮位を東西に補間して与える。外縁は潮位リザーバとして扱う。
気象庁公表の2026年潮位表基準面高（Z1 -0.926m、MR -0.867m、比較用TK -1.141m）を補正する。
ただしGtTM側との鉛直基準面の差や、2点を広い境界へ補間する近似は残る。
250m格子、20秒刻み、48時間助走、粘性5m²/s、底面抵抗係数0.0025。
風、河川流、成層、二枚潮、干出・冠水は含まない。流速・反流・渦は実測未検証。

## 数値確認

- 変水深の静水が静止すること、内部セルの質量収支、陸面流量ゼロ、閉鎖水域のエネルギー減衰を確認。
- 本ケースの内部セル連続式残差最大2.2e-13m。これは開境界リザーバを含む全領域体積誤差とは異なる。
- 境界に使用していない東京の天文潮位との24時間・30分刻みの水位RMSEは約6.8cm。実測潮位や流速の検証ではない。
- 時間刻み10秒との概算釣り位置のベクトル差：RMS約0.00039m/s。
- 格子500mとの同差：RMS約0.0276m/s。8:30の流速は250m版約0.097kn、500m版約0.046kn。弱流時の格子感度が大きい。
- 助走24時間との同差：RMS約0.0096m/s。初期条件の影響は残る。

元結果は`data/tidal-report*.json`、比較は`data/tidal-sensitivity.json`。
これらは数値的整合性・感度の確認であり、実際の局所流の誤差推定ではない。

## Tool 04 / 潮位曲線と共通デザイン

東京湾の潮と流れ（TIDE & CURRENT MAP）として、cutlassfish.tokyoの色（背景#06080f、アクセント#4fd0d6、金#e7b765）、Oswald / Noto Sans JP、既存ロゴ、ツールナビへ合わせた。

地図下の潮位曲線は、気象庁の東京TK・油壺Z1・布良MRの毎時値と公式満干潮を使う。基準は各地点の潮位表基準面、JST。翌日0時を含み、欠測を補外しない。曲線は形状保持の三次Hermite補間。満干潮は曲線から推定せず、公表値を節点として反映。上げ下げと流向・潮止まりは一致するとは限らない。参考地点と選択位置の距離も表示する。

「今日」はJSTの当日・直近の毎正時へ切り替える。10/24事例モードからは沖合の公式推算へ切り替える。潮位表と地図は独立に取得し、潮流側が取得できなくても潮位表を表示できる。

気象庁数値データは無料利用でき、利用条件は https://www.jma.go.jp/jma/kishou/info/coment.html 。出典と加工内容を画面に記載した。

2つの表示と使用中の方式の説明、地点選択と潮位参考地点の自動連動、グラフと30分刻みの時刻選択の同期を追加。100m/250mは精度ではなく格子間隔として説明する。

検証：固定幅の時・分フィールド（空白を含む）、翌日0時、公式満干潮の値、補間の範囲保持、欠測を横断しないことをテスト。390/1100/1440pxの実ブラウザーで潮位表の切替・時刻連動・グラフタップ・メニュー・説明の開閉・今日への切替を確認。既存のGoogle SDKアダプターと標準地図のピンチも回帰確認。実Google APIキーの認証は未確認。

### 地図の操作と現在地

地図内の複数指の操作とSafariのgestureイベントは、ブラウザ全体の拡大に伝えないよう地図内で処理します。地図外のページ拡大は利用できます。スマホの入力・選択欄は16pxにし、iPhoneの入力フォーカスによる自動拡大を抑えます。

「◎ 現在地」は押したときだけ端末の位置情報を取得し、地図と選択地点を移動します。位置情報の許可が必要です。高精度を要求し、古い位置のキャッシュを使わず、15秒で取得を打ち切ります。自動追跡や位置の自動保存は行いません。保存済み釣り位置は上書きしません。取得拒否・失敗・時間切れでも他の操作を続けられます。表示範囲外の場合はその旨を表示し、潮流の値を代用しません。Google地図と標準地図の両方で利用できます。Google地図では既存の地図を移動し、作り直しません。

現在地への移動は、上部のボタンと地図右側の「現在地」の両方から使えます。取得中・取得失敗後の状態は両ボタンで共有します。Google標準のカメラ操作ボタンは非表示にし、地図右側の操作ボタンにまとめます。
